# HighLevel Voice AI editor: public API coverage

Checked: 2026-07-16
Scope: official HighLevel developer documentation and first-party HighLevel support material only. UI controls are **not** treated as API capabilities unless they appear in a public request/response contract.

## Bottom line

No: the public API does not expose every option shown in the Voice AI editor.

The documented `GET /voice-ai/agents/:agentId` and `PATCH /voice-ai/agents/:agentId` contract covers the basic identity/prompt/voice/language fields, a limited set of call controls, translation, phone assignment, working hours, backup behavior, and post-call workflows/notifications. Actions have their own public CRUD endpoints and OAuth scopes. The public agent contract does **not** document the model, response speed, interruption sensitivity, temperature, STT/keyword/pronunciation controls, detailed voice/audio processing, reporting-email configuration, system prompts, or outbound disclosure/intent controls.

“Unavailable/undocumented” below means there is no public HighLevel contract establishing that the setting can be read or written. It does not claim HighLevel's own UI lacks an internal endpoint.

## Exact documented Agent fields

The current Create/Patch Agent contract documents these writable fields:

`agentName`, `businessName`, `welcomeMessage`, `agentPrompt`, `voiceId`, `language`, `patienceLevel`, `maxCallDuration`, `sendUserIdleReminders`, `reminderAfterIdleTimeSeconds`, `inboundNumber`, `numberPoolId`, `callEndWorkflowIds`, `sendPostCallNotificationTo`, `agentWorkingHours`, `timezone`, `isAgentAsBackupDisabled`, and `translation`.

Create additionally requires `locationId`; Patch identifies the agent in the path and requires `locationId` as a query parameter. The documented Get/Create/Patch response represents the same core configuration fields. Fields returned by a live service but absent from this public request contract should be treated as read-only/unstable unless HighLevel adds them to the contract.

## OAuth and the current app

The official scope table maps:

- `voice-ai-agents.readonly` to list/get agents.
- `voice-ai-agents.write` to create/patch/delete agents.
- `voice-ai-agent-goals.readonly` to get an action by ID.
- `voice-ai-agent-goals.write` to create/update/delete actions.
- `voice-ai-dashboard.readonly` to call logs and the `VoiceAiCallEnd` webhook.

This project currently requests read-only Voice AI access (`voice-ai-dashboard.readonly`, `voice-ai-agents.readonly`, and, where enabled, `voice-ai-agent-goals.readonly`). Therefore, **even the settings marked Supported above are not editable with the app's current OAuth grant**. Enabling edits would require adding the appropriate write scope to a new Marketplace app version and having installations reauthorize. It would also change the product's current decision-support-only posture; API availability alone should not silently broaden that authority.

## Implementation rule

Only offer an edit control when all three are true: the setting is in the public write schema, the installation token has the documented write scope, and the product has explicitly authorized applying changes. Otherwise show it as observed/read-only, recommendation-only, or unavailable rather than attempting an undocumented payload.
